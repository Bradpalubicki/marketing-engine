1. Dashboard Overview

The main dashboard (/dashboard) is your patient acquisition at a glance — live reads from the database every time you load the page.

Recent Leads table

Shows the 10 most recent leads across all locations. Full lead list is at /dashboard/leads.

Locations panel

Shows up to 5 locations with leads-this-month counts. Click any location card to navigate to that location's detail view.

AI Insights

Weekly Claude-generated performance summaries per active location. These appear here after 7 days of data — the analysis runs every Sunday at midnight UTC. Until then, you'll see a placeholder message. Insights cover leads, booking rate, spend, and CPL for the trailing week.

All dashboard metrics are live reads — no caching. If you refresh, you get the current DB state.

2. Locations

A location is a single clinic. Each one gets its own campaigns, leads, GBP automation, and reporting.

How to add a location

  1. Click Locations in the left nav.
  2. Click Add Location (top right).
  3. Fill out the form — name, city, state, address, monthly budget, and GBP location ID if you have it.
  4. Save. The location is created with status = active.

What happens after you add a location

The system fires a location/activated Inngest event. The Campaign Factory picks this up and:

  • Runs a compliance check on all generated ad copy
  • Provisions a Google Ads sub-account under NuStack MCC (if Google Ads is enabled)
  • Creates placeholder campaign records for all three platforms: Google, Microsoft, Meta
  • Splits the monthly budget: 60% Google, 40% Microsoft
  • Writes campaign records to the campaigns table with status = paused until platform API is live
Google Ads and Meta Ads are currently in pending approval state. Campaigns are created as records in the DB but not live on the ad platforms yet. See Section 10 (Settings → Integrations) for the current status of each integration.

Location card status indicators

Each location card shows leads this month. Location status is either active or inactive.

3. Campaigns

The Campaigns page shows all campaigns across all locations with 30-day spend and performance data.

MTD Spend cards

Four cards at the top: Total, Google, Microsoft, Meta — all month-to-date from the spend_records table. Shows "—" if no ad platform is connected.

Spend chart

Daily spend by platform for the last 30 days. Pulls from spend_records. If Google/Meta/Microsoft is not connected, the corresponding line is flat.

Platform connection banners

If a platform isn't connected, you'll see a banner at the top. These are controlled by feature flags:

  • FEATURE_GOOGLE_ADS=true — removes the Google banner, enables spend ingestion
  • FEATURE_META_ADS=true — removes Meta banner
  • FEATURE_MICROSOFT_ADS=true — removes Bing banner

Campaign performance table

Only appears if spend data exists. Shows per-campaign: spend (30d), clicks, impressions, CTR, leads, and CPL. Leads are matched by utm_campaign → campaign name.

Pre-flight compliance checks

Every campaign runs a pre-flight before activation. The system blocks campaigns that fail any of these gates:

CheckGate TypeWhat it tests
BID_STRATEGYBLOCKeCPC is deprecated Oct 2024 — will not activate
TCPABLOCKTCPA opt-in language must be confirmed on all lead capture forms
LP_SCOREBLOCKLanding page must score ≥ 65. Below 65 = campaign blocked
AUTO_APPLY_RECOMMENDATIONSBLOCKGoogle auto-apply recommendations override manual bids — must be off

Campaign statuses

active = live on platform. paused = created in DB but not live (platform API pending). failed = campaign factory hit an error. Check campaign_factory_notes on the location record for details.

Note: The Google Ads API is in Explorer Access (developer token pending Standard upgrade — 2–6 week approval). Microsoft Ads is blocked on Azure App Registration. Neither is live yet. Campaigns exist in the DB as placeholders until approvals land.

4. Leads

All inbound patient leads. A lead is created when someone submits a form, calls via CallRail, or is created via webhook.

How leads flow in

  • Web form: POST to /api/leads/create → lead record created → lead/created Inngest event fires → nurture sequence starts
  • CallRail: CallRail webhook → /api/webhooks/callrail → lead created with source = call
  • Twilio SMS reply: Handled via /api/webhooks/twilio
  • Appointments webhook: /api/webhooks/appointments — external booking systems can push appointment confirmations

Lead status pipeline

StatusMeaning
newJust created. SMS sent within 60 seconds.
contactedInitial SMS sent successfully. Nurture sequence active.
bookedConsultation scheduled.
showedPatient showed up for their appointment.
no_showedBooked but didn't show.

Lead fields captured on every lead

name, phone, email (optional), location_id, source (form/call/chat), utm_source, utm_medium, utm_campaign, utm_content, utm_term, landing_page_id, first_touch_source, gclid (Google click ID), created_at, status, nurture_sequence_step.

Lead quality rating

Each week's report email contains 1–5 star rating buttons. When Brad clicks a rating, it's stored in the DB via /api/leads/rate-quality. This feeds back into the weekly AI narrative — the system uses it to assess lead source quality over time.

Lead table filters

You can filter by: ?location=, ?status=, ?source= in the URL. The table shows the top 100 leads matching the filter.

Lead export

/api/leads/export — CSV download. Auth required.

Nurture sequence

Fires automatically on every new lead. 5-step sequence:

  1. Immediately: SMS to patient with booking link
  2. +2 hours: Follow-up email with booking link (if email provided)
  3. +24 hours: Retargeting audience event fired
  4. +72 hours: Internal alert email to location manager if lead is still uncontacted
  5. +7 days: Final re-engagement SMS ("Reply YES for a callback or STOP to opt out")

Nurture pauses automatically if the lead is booked, showed, or no-showed. A nurture_paused flag can also be set manually.

6. Reviews

The Reviews section shows all Google Business Profile reviews for your connected locations, with AI-drafted responses queued for approval.

How GBP reviews are pulled

The gbp-reviews Inngest function runs every 4 hours. For each location with a GBP profile connected (gbp_location_id set), it:

  1. Calls the Google Business Profile API to fetch all reviews
  2. For each new review (not already in review_responses table), generates an AI draft response via Claude
  3. Saves the draft with status = pending

Reviewing and approving responses

Review queue is shown in the Reviews dashboard section. Each pending review has the AI draft pre-filled. Edit it if needed, then approve. Once approved, the response is submitted back to GBP via the API.

GBP connection requirement

Reviews only populate if the GBP OAuth is connected. Go to Settings → GBP to connect your Google account. The location also needs gbp_location_id set.

The GBP OAuth needs a refresh token. After connecting, copy the token shown and add it to Vercel as GBP_REFRESH_TOKEN, then redeploy. See Settings → GBP for the full walkthrough.

7. Posts

Automated GBP post generation. Every Monday at 9AM UTC, the system generates 4 posts per active location and schedules them for the coming week.

How it works

  1. The gbp-posts Inngest function runs Monday 9AM UTC
  2. For each active location with a gbp_location_id, Claude generates 4 post variants (typically a mix of promotional and informational types)
  3. Posts are saved to the gbp_posts table with status = scheduled
  4. If GBP credentials are set, the function publishes each post directly to GBP at 6-second intervals (rate limiting)
  5. Successfully published posts get status = published. Failed ones get status = failed

Post scheduling

Posts are spaced 2 days apart, starting the day after generation. So Monday generation → posts on Tuesday, Thursday, Saturday, Monday.

What gets published automatically

If GBP OAuth is connected and gbp_location_id is set on the location, posts publish automatically without any action from you. No approval queue — the AI generates and publishes directly.

If the GBP refresh token is missing or expired, posts will save with status = scheduled but not publish. You'll see failed entries in the posts table. Reconnect GBP in Settings → GBP.

8. Reports

Two types of reports: the in-app reports dashboard and the weekly email report.

In-app reports page

Shows per-location performance metrics: leads, booked, showed, conversion rate, ad spend, CPL, and top source — for this week, last week, and the last 30 days side-by-side.

Also shows the most recent weekly report (HTML) filed for each location, and a quality rating history.

Weekly email report

Sends every Monday at 8AM UTC to all org admins for locations with weekly_report_enabled = true. Each email contains:

  • 4 metric cards: new leads, consultations booked, patients showed, total ad spend
  • AI-generated narrative (3 parts: headline, what worked, what's next)
  • Ad spend breakdown by platform (Google / Microsoft / Meta)
  • Google Business Profile rating (if GBP connected)
  • 1–5 lead quality rating buttons (your feedback goes into the AI's next report)
  • Link to full dashboard

How to enable weekly reports for a location

Set weekly_report_enabled = true on the location record. It's on by default for active locations.

Who receives the reports

All Clerk org admins (role = org:admin) for the organization that owns the location. The system pulls emails from Clerk's API each send cycle.

Report storage

Each sent report is stored in sem_weekly_reports (one row per location per week). The in-app view renders the stored HTML directly.

9. Conversion Health

Located at /dashboard/tracking (labeled "Conv. Health" in the nav). Shows whether conversion tracking is firing on each platform for each location.

What it shows

Per location, per platform (Google / Meta / Microsoft):

  • Firing — conversions recorded in the last 24 hours
  • Not Firing — has historical data but zero conversions in last 24h
  • Unknown — no snapshot data yet (or platform not connected)

Data source

Reads from sem_platform_daily_snapshots — the same table populated by the daily spend reporting job. Conversion data starts building after platforms are connected.

History threshold

The "has history" flag requires 60 days of snapshot data. Before 60 days, the page shows "Conversion history builds after 60 days of platform snapshot ingestion."

11. What Runs Automatically

Everything below runs without you touching anything. These are Inngest background functions — they fire on a schedule or in response to events.

Daily Spend Reporting Scheduled
Every day at 6:00 AM UTC

Pulls yesterday's spend data from Google, Meta, and Microsoft (if connected and feature flags are set). Writes spend, clicks, and impressions into spend_records per campaign per platform. This is what populates the spend chart and MTD cards on the Campaigns page.

If a platform API call fails, it logs the error and returns — it does not retry automatically.

QS Daily Snapshot Scheduled
Every day at 6:00 AM UTC

Pulls Quality Score data from Google Ads API per organization. Writes to sem_platform_daily_snapshots. Currently using placeholder data (real Google Ads API call pending Standard token approval). Powers the Conversion Health page and the context-builder for AI prompts.

GCLID 90-Day Purge Scheduled
Every day at 2:00 AM UTC

Deletes leads from the leads table where source = google_ads, no conversion was recorded (converted_at is null), and the lead is older than 90 days. This is a HIPAA data retention requirement (Ch 54 compliance). Logs the purge count. If it fails, logs the error — does not alert.

Budget Pacing Check Scheduled
Every 4 hours

For each active budget allocation, compares actual spend vs. weighted expected spend (day-of-week weights + holiday detection). If overspending by >15%, reduces daily budget by 10%. If underspending by >15%, increases by 10%. Maximum daily budget is capped at 110% of (monthly budget ÷ 28). Skips platforms with feature flags disabled.

Day weights: Monday 1.2x, Thursday 1.15x, Friday 0.9x, Saturday 0.75x, Sunday 0.8x. Holidays reduce expected spend by 50%.

GBP Review Fetch & AI Draft Scheduled
Every 4 hours

For each location with a GBP profile, fetches all reviews from the GBP API. For each new review (not already in the DB), generates an AI draft response using Claude and saves it with status = pending. Updates the review count and last-synced timestamp on the GBP profile record.

Auction Insights Weekly Pull Scheduled
Every Monday at 7:00 AM UTC

Pulls competitor auction insights from Google Ads (impression share, overlap rate, outranking share) into sem_competitive_snapshots. Currently using placeholder data pending Google Ads Standard token. This data feeds into the AI context-builder for escalation and optimization prompts.

Optimization Cadence Weekly Scheduled
Every Monday at 7:30 AM UTC

Reviews the past 7 days of spend data per org. If an account spent >$500 with zero conversions, it creates a Level 3 alert in sem_platform_automated_actions tagged for the #marketing-engine-alerts Slack channel. This catches the worst-case scenario (money spending, nothing booking) automatically.

GBP Weekly Post Generation Scheduled
Every Monday at 9:00 AM UTC

Generates 4 GBP post variants per active location using Claude. Schedules them 2 days apart. If GBP OAuth is connected, publishes directly to GBP at 6-second intervals (API rate limit). Posts that fail to publish get flagged as failed in the DB.

Weekly AI Performance Insights Scheduled
Every Sunday at midnight UTC

For each active location, aggregates the past 7 days of lead and spend data. Sends to Claude with context (leads, booked leads, booking rate, spend, CPL). Saves the AI-generated analysis to the ai_insights table. This is what appears in the Dashboard Overview AI Insights section.

Monday Weekly Report Email Scheduled
Every Monday at 8:00 AM UTC

For each active location with weekly_report_enabled = true: aggregates this week vs. last week metrics, fetches org admin emails from Clerk, generates an AI narrative summary, and sends an HTML report email via Resend to all org admins. Stores the report in sem_weekly_reports. Generates quality rating tokens (1–5) for the lead quality feedback block in the email.

Campaign Factory Event-Triggered
Fires on: location/activated event

Triggered when a new location is activated. Runs pre-flight compliance check, generates RSA copy + Meta copy + sitelinks + callouts using Claude. Creates campaigns on Google Ads (if feature enabled), Microsoft Ads (if feature enabled), and Meta (if feature enabled). Writes campaign records to DB. Updates location status to complete or failed.

Lead Nurture Sequence Event-Triggered
Fires on: lead/created event

5-step sequence per lead: SMS (immediate) → email (2h) → retargeting event (24h) → internal alert (72h) → final SMS (7 days). Each step checks if the lead was booked or paused before sending. All nurture events are logged to nurture_events table.

IP Exclusion Auto-Apply Event-Triggered
Fires on: sem/click.suspicious event

Handles suspicious click detection. When a suspicious click is detected, logs a Level 1 auto-applied action in sem_platform_automated_actions. Will apply the IP exclusion to Google Ads via CampaignCriterionService once the Google Ads API Standard token is approved.

PES Critical Alert Event-Triggered
Fires on: pes/calculated event (only when PES < 55)

PES = Platform Efficiency Score (composite of ROAS, pacing, Quality Score, creative health). When PES drops below 55, this function: identifies the lowest-scoring component, generates a diagnostic paragraph using Claude, logs the alert to sem_pes_alerts, sends a Slack message (if SLACK_ALERT_WEBHOOK_URL is set), sends an email to Brad. Then waits 24 hours — if the alert isn't marked resolved, sends a follow-up escalation email.

Copy Result Feedback Loop Event-Triggered
Fires on: sem/copy.result.recorded event

Updates sem_copy_performance_log with the test result (WINNER / LOSER / INCONCLUSIVE) for a copy variant. This log feeds into the AI context-builder, which injects top 5 / bottom 5 copy variants into escalation prompts.

Weekly Cron Report API Scheduled
Weekly (via /api/cron/weekly-report)

An additional cron endpoint for generating weekly reports. Can be triggered externally (e.g., Vercel cron). Works alongside the Inngest weekly-report-email function.

12. Troubleshooting

Campaign won't launch — shows status "paused" or "failed"

Check the campaign_factory_notes column on the location record in Supabase. If it says "Compliance violations", the copy generated contained prohibited terms (Rx drug names, etc). Check campaign_factory_status — if it's running, the factory is still in progress. If it's failed, check campaign_factory_notes for the specific gate that blocked it (most common: TCPA not confirmed on the compliance profile).

Lead came in but no SMS was sent

Check the nurture_events table for this lead. If step 1 shows status = failed, Twilio rejected the SMS — likely a number formatting issue or Twilio account balance/status. Confirm TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, and TWILIO_FROM_NUMBER are set in Doppler. Check Twilio dashboard for the error code on the failed message.

Campaign on HOLD unexpectedly

Campaign status changes to paused in two scenarios: (1) the campaign was created as a placeholder while platform API approval is pending, or (2) a budget pacing rule reduced the daily budget to the $5 minimum and a manual pause followed. Check the budget_allocations table for the current_daily_budget value. The pacing job runs every 4 hours — if daily budget hit $5 and remained there, spend data suggests the campaign is severely over-pacing.

Weekly report not sending

Check Inngest dashboard for the weekly-report-email function run for that Monday. Common causes: (1) weekly_report_enabled is false on the location, (2) no Clerk org admins have a primary email address, (3) Resend API key is not set in Doppler. The function logs errors to Inngest — check the step that failed.

GBP post not publishing

Check the gbp_posts table for status = failed. This means the GBP API call failed. Most common cause: the GBP_REFRESH_TOKEN env var is missing or the token has expired. Go to Settings → GBP and reconnect the Google account to generate a fresh refresh token. Add the new token to Vercel env and redeploy.

Reviews not showing up in the Reviews section

The review sync runs every 4 hours. If nothing is showing: (1) confirm GBP OAuth is connected (Settings → GBP shows "Connected"), (2) confirm the location has gbp_location_id set, (3) check the gbp_profiles table for the location — last_synced_at will tell you when the last sync ran. If last_synced_at is stale, the GBP API may be returning an error — check Inngest dashboard for the gbp-reviews function.

Conversion Health showing "Not Firing" when it should be

The conversion health dashboard reads from sem_platform_daily_snapshots, populated by the daily spend reporting cron. If Google/Meta/Microsoft feature flags are off, no snapshots are written. If the cron is running but conversions are zero, that's accurate — the platform isn't recording conversions. Also note: the status shows "Unknown" until 60 days of history exist.

AI Insights not appearing on dashboard

Insights first generate after 7 days of data. The job runs every Sunday at midnight UTC. If it's been more than 7 days and still no insights: check the Inngest dashboard for the ai-insights function run on the most recent Sunday. If the step "gather-performance-data" returned 0 leads and 0 spend, there's no data to analyze and no insight is written.

TermDefinition

Lead Quality RatingThe 1–5 rating in the weekly report email. Used by Brad to signal whether the week's leads were high quality. Feeds into the AI narrative over time.
Nurture SequenceThe automated 5-step follow-up workflow triggered for every new lead: SMS → email → retarget → internal alert → final SMS.
OrgAn organization in Clerk. Typically maps to one clinic operator. Can have multiple locations.
PESPlatform Efficiency Score — composite score (0–100) of ROAS, pacing, Quality Score, and creative health for an account. Scores below 55 trigger an automated alert to Brad.
Pre-Flight CheckThe set of validation gates the Campaign Factory runs before activating a campaign. BLOCK gates = campaign cannot go live. All must pass.
RSAResponsive Search Ad — Google's standard ad format with multiple headline and description options. The engine generates RSA copy using Claude.
Spend RecordsDaily rows in the spend_records table — one per campaign per platform per day. Populated by the daily spend reporting cron.
TCPATelephone Consumer Protection Act. Requires opt-in language on lead forms before the system can send SMS messages. Confirmed via the compliance profile — missing TCPA = campaign blocked.
Weekly ReportThe Monday morning email sent to each org admin. Contains lead volume, booking metrics, ad spend, and an AI-generated narrative. Stored in sem_weekly_reports.
